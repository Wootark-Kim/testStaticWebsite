Learning Journal on React

Over the past few days, I've been keeping notes on some React fundamentals. Here's some of the following topics and points I've learned

What is a component?:

A component is just a function that returns html (or technically jsx). A component is not the file itself. In other words, a React component is just a function defining what a certain part of a website looks like.

What is a state?

A state is just a variable holding some data that React watches. When state changes, React automatically updates (re-renders) the component on the browser.

Declaring state and the usage of “usestate” function

A React component declares a state through the usestate function. For example:

Example 1

const [message, setMessage] = useState("");

This code means: “Create a piece of state called message. Initially it is an empty string. Give me a function called setMessage to update it”

Example 2

const [orders, setOrders] = useState([]);

This code means: “"Create a piece of state called orders. Initially it is an empty array. Give me a function called setOrders to update it."

Example 3

const [customer, setCustomer] = useState({ name: "", email: "", password: "" });

This code means: “"Create a piece of state called customer, and give me a function called setCustomer that I must use whenever I want to change it. Initially, customers should contain this object."

How React components are organized

A React component seems to be organized in this fashion:

  1. Imports
  2. State creation/declaration
  3. Event Handlers
  4. Custom Helper Functions (optional)
  5. Returning jsx (or other forms of ui)
  6. Export

React vs ReactRouter

A React Router is a routing library “add-on” for React. React Router provides routing functionality. For example, it introduces these 3 tags: <BrowserRouter> <Routes> and <Route>

BrowserRouter supplies the URL data

Routes uses URL data to pick a match

Route defines the mapping

These 3 tags must be used in conjunction to provide any meaningful results.

Personal thoughts on React

I can see how React can be incredibly powerful and useful, but it does, however, feel overly complex for a beginner to learn. Perhaps it is because it feels abstract. A lot of sense of "groundedness" disappeared when compared to vanilla html + css + and js coding, especially in regard to visual spacial clarity. Often in vanilla html, you pretty much understand that a given file is equal to one page, and the contents written from top to bottom often appear in the same sequential order on the browser.

With React, however, everything is compartmentalized in components, and several components from multiple files can be referenced into one file. React also, depending on the project, utilizes JavaScript or TypeScript, which in itself isn't too bad, but then you realize there's a lot of React specific methods to learn and you need to figure out how to read them.

A tutorial video I was watching said something that kind of resonated with how I felt when learning React: "When you are learning React, you quickly feel like you're not learning how to read or write JavaScript or TypeScript. You don't even feel like you're learning how to code or becoming a better code reader. The whole time it just feels like you're learning how to deal with React's layer of abstractness"
