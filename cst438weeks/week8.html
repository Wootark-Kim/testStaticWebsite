List the 5 most important things that you learned in the course, and why you chose them. Were there topics would you like to see added or deleted from this course?

1. N-th service layer architectural system 2. Fundamentals of code review pipeline on GitHub 3. UML Use Case diagrams 4. Selenium + testing principles 5. PD vs Agile

The N-th service layer architectural system was one of the most valuable fundamentals I've learned from this course. Technically the course didn't explicitly teach us the principles of N-th layer but inadvertently did by teaching us Spring Boot for backend. Once it clicked why Controllers, Entities, Services, etc. were written as their separate layers, I finally felt that I started to understand what it means to practice engineering principles in software/web designs.

I'm also glad the class taught us how to perform code reviews on the GitHub platform (assigning reviewers, merging, etc.). For this topic, it's not the principle of code review that was hard for me to understand but rather navigating the UI of GitHub itself. Feels like an uphill battle at times with unintuitive UI designs and, often times, hidden/tucked-away options.

I'm really glad that we were taught on how to properly draw up a UML Use Case diagram. Knowing how to structure and place a code is not the only "engineering" practice of software engineering. I always did believe that Knowing how to properly draft up an overview of an application and understanding how the services should be connected was just as valuable as well.

I chose Selenium as one of my 5 valuable learnings just because I thought it was cool to see my browser "come alive." With that being said, learning about the principles of software testing was certainly valuable as I now understand best practices on how to configure and set up testings. This should especially come in useful on my future personal projects.

I chose PD vs Agile as quite important because I've heard the term agile so many times yet never truly understood it until now. I think part of the reason why it took my awhile to understand it is due to the technical jargons and the abstracted way in which most websites explained it. At the end of the day, it's just a more organized way to iteratively develop a software/project. An upgrade from the "group project 'iterative' wing-it" days of high school.
