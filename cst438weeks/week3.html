Understanding Software Engineering

Blessed be Git. There are too many good points about using Git for source code management. Makes collaboration feel pragmatic.

For starters, the ability to branch and merge removes a lot of issues of applications being "temporarily disabled" when another developer is making major changes. It's also great that it keeps track of who made each changes and when. Honestly these 2 points alone make learning Git worthwhile.

I feel that dealing with Git's or GitHub's logical conflict feels a bit unintuitive. But then perhaps that may be more of an IDE issue. At first, it wasn't very clear at all on whether the left or the right side was the developer's change vs what is already stored in the repository. Git itself also seems to behave simply more as a "text combine" in that there's no logic or suggestions on possible code logic conflicts.
