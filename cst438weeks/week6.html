Week 6

( 29 June 2026 ) to ( 4 August 2026 )

Write a weekly entry describing important things you learned this week.

I believe that my freestyle coding attempt is indeed starting to help me build intuitive understanding of architecture and design philosophy. Sometimes you can learn a concept, but it may not truly hit you until you are forced to reckon with it and build it ground up from a blank canvas.

Take for instance when I attempted to utilize my knowledge of Spring's strict controller -> service -> repository -> database layer knowledge on an Express.js backend framework. I am currently involved in an open-source internship where I am contributing toward a feature on a web scrape application called Maxun. So far, our course has taught the Spring boot application but Maxun utilizes Express.js as its backend framework. When attempting to apply Spring's architectural principle to Maxun's folder structure, I quickly found myself asking "What is going on here? Where's the controller file. Where is the repository file?" and so forth.

This is when I realized the concept of "opinionated" and "non-opinionated" framework where certain framework enforces or highly encourages n-th tiered layer application and where others do not. Then all of a sudden, it clicked. I intuitively understood what "layered architecture" truly meant. It's not a set principle but a dynamic concept. Spring's principle of layered architecture was simply just one design philosophy. Express.js did not enforce any certain number of layer because it is supposed to be dynamic. It is non-opinionated not because it wants us to disregard utilizing layers but because so we can design any custom n-th layer level system design.

Then I started to have strong feelings about how I could've of had organized Maxun's project structure. Whereas a few days ago I would have taken a projects file structure at face value, now having enough knowledge to start having my own opinions gave me a fresh breath of acknowledgement that I am indeed making progress on what it means to be a software "engineer."
